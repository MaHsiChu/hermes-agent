# 统一 Session 任务看板

入口：Hermes 左侧固定的 **统一看板**，随插件注册常驻，不依赖打开哪个任务。原来的 **会话协作** 页面仍可使用，也提供看板入口。外部任务详情内也有“返回看板”，不会关闭其他任务标签。

看板合并当前 Hermes 会话、Codex App 会话、Claude Code 会话及 Hub 派发任务。
任务就是原 Session 的视图，打开时不会复制对话或创建替代会话。

## 使用

- 切换看板 / 列表；支持关键字搜索和“未完成 / 已完成 / 全部任务”快捷筛选。默认保留全部任务；完成未查看和完成已查看均计入已完成，空闲、中断、状态待确认不被推断为完成。
- “筛选”弹出多条件配置，支持满足全部 / 任一条件、添加 / 删除 / 清空。可选标题、状态、引擎、项目、更新时间、Session ID、最新动态、执行通道、Hub 已跟踪、实时来源；枚举支持多选，文本支持包含 / 不包含 / 等于 / 不等于，日期按本地日历日比较，所有字段支持为空 / 不为空。未填写的条件不生效。
- 快捷筛选、自定义条件、搜索和会话范围共同生效；“全部任务”表示当前会话范围内的所有完成状态，并不取消其他条件。无结果时“重置筛选”保留字段、排序和分组设置。
- 按待操作优先、最近更新、最早更新、标题排序。
- 按状态、引擎、项目目录分组，或不分组。
- 字段配置：引擎、项目、更新时间、Session ID、最新动态、执行通道、Hub 已跟踪、实时来源。眼睛按钮控制显隐；拖动把字段移到目标字段之前，也可用上下按钮调整顺序；支持恢复默认。标题和状态固定展示。这一版配置现有 Session 字段，不创建业务自定义字段。
- 筛选条件、快捷筛选、字段显隐与顺序保存在当前桌面的插件显示偏好中；旧版引擎 / 状态筛选自动转为条件，保留原先显示的字段。
- 卡片右上角可复制任务引用，粘贴到 Hermes 对话。用户消息与 Agent 回复中的引用都显示实时任务卡，点击打开对应会话。
- Hermes 会话直接打开原对话。外部任务在 Hermes 内打开原会话记录；Codex / Claude Desktop Code 均提供原 App 打开入口；Claude 使用原生协议请求打开，操作系统回执不代表 App 已确认导航。
- 任务卡下方“已开启 / 已关闭”可点击切换；这是用户管理标记，与运行、完成、已读状态独立。关闭不会停止、归档或删除原 Session，也不会在任务下次运行时自动重开。元数据保存在 Hub SQLite，重启后保留；待创建任务获得原生 Session ID 后沿用该标记。详情页也能切换。
- 快捷筛选新增“已开启 / 已关闭”；它们按人工标记筛选，原有“未完成 / 已完成”仍按执行状态筛选。“是否关闭”也可作为自定义筛选条件或显示字段。
- 按用户选择，点击卡片继续在 Hermes 内打开；卡片和详情页单独提供“在 Codex App 中打开”。该按钮先确认 App 已选中原 Session，再由 Session Hub 的 Windows 适配器调用固定的 `codex://threads/<id>` 协议请求激活窗口（仅接受合法 UUID，Windows 是否给予前台焦点仍由系统决定）；失败显示反馈，不创建替代会话。
- Hermes 内是本地记录阅读视图，不能完全复用 Codex 原生的输入区、附件栏、工具交互和文件审查界面。需要完整原生界面时使用 Codex 按钮。

## 状态

| 状态 | 显示 |
|---|---|
| 运行中 | 淡黄色，状态点呼吸与底部流动线 |
| 需要操作 | 较深黄色、左边强调线、状态点呼吸 |
| 完成未查看 | 淡绿色、状态点呼吸 |
| 完成已查看 | 中性灰色 |
| 排队 / 待开始 | 淡蓝色 |
| 空闲 | 中性灰色，不据此宣称任务成功 |
| 已中断 / 待确认 | 单独显示，不当作完成 |

页面和普通控件使用应用中性背景 `--ui-surface-background`；原来的蓝底来自误用强调填充 `--ui-bg-primary`，已移除。仅任务卡保留状态提示色。

热更新修复：旧任务详情标签保留的 `<style>` 曾在 DOM 后方覆盖新版看板，导致控件已更新但整屏蓝底仍在。现在样式由插件生命周期统一注册到 `document.adoptedStyleSheets`，卸载时清理；看板、详情和引用不再各自注入全局样式。保留的旧任务标签无需关闭，其旧样式也不能覆盖新版。

遵循系统“减少动态效果”设置。打开外部记录并成功加载后，标记当时的完成结果为已查看。
新的完成结果会再次变为未读；读取列表或 Agent 查询状态不会自动清除未读。
只表示一轮执行的状态，完成并不保证任务目标已验收。

Hermes 状态直接订阅桌面的现有状态源，外部 Session 每 5 秒拉取看板快照；App 目录和审批状态在后台约每 10 秒刷新。
断线时保留上次快照并显示错误。Claude 仅能展示其接口或已保存记录提供的状态，不能完整镜像 Desktop 审批弹窗。

默认显示正在使用和 Hub 已跟踪的任务；“包含近期历史”增加最近 200 条本地历史，底部显示已载入 / 总数。
Codex App 目录沿用已有 App 工具的最近任务窗口；云端历史、未连接机器、App 未返回且本地不可见的会话不在可见范围。
Hermes 列表来自当前桌面已加载的会话清单。界面不是对所有远程历史的完整导出。

## Agent 创建与引用

新增 MCP 工具：

- `hub_create_task_session`：创建可在看板显示的新任务，返回持久任务引用。
- `hub_task_board`：查询外部任务状态（Hermes 自身会话由桌面实时合并）。
- `hub_task_reference`：把 Session ID / Hub job ID 解析为实时引用。

示例要求：

> 用 hub_create_task_session 在 Codex App 新建“接口评审”任务，只分析项目接口；将返回的 reference 原样显示在回复中。

> 用 hub_task_reference 查询 codex:<原 Session ID>，把它作为任务卡引用到本次对话。

新建 Codex 默认走 App 通道，保留原 App 权限；创建 Claude 任务需要明确选 CLI 和工作目录。
不支持通过此接口创建 Claude Desktop 窗口。Hermes 新任务按钮进入原生新对话，由用户在对话内输入并启动任务；新增 MCP 创建工具目前面向 Codex / Claude。
返回 queued 只表示排队，Agent 必须查看后续状态。重复提交同一请求使用相同 request_key；不会因超时自动重发。
引用跟随持久 Session，后续轮次继续使用同一个引用。

## 已打开任务的左侧入口

从看板打开 Codex / Claude 任务后，同一工作区也会显示在左侧「会话」列表中：标题、引擎标识和状态点随看板刷新；点击回到原任务，重复打开不增加条目。会话搜索支持标题、引擎和 Session ID。条目旁的 × 关闭该工作区标签，不改变任务的开启/关闭标记，也不停止引擎。

实现通过通用 `host.openWorkspace` 的可选 `sidebarSession` 展示参数，复用原 pane 注册及关闭生命周期，不向 Hermes 后端伪造 Session。本次需要新版桌面外壳，构建已更新；重启 Hermes 后从看板打开任务生效。旧版桌面仍可打开任务，但会忽略这项侧栏展示参数。

验证：20 项桌面 SDK / 会话列表 / 工作区联动测试通过，插件浏览器验证状态更新通过；TypeScript 与修改范围内 lint 检查通过。当前正在运行的旧窗口未强制重启。

## Claude Desktop Code

Claude 详情页已采用与 Codex 相同的共享对话布局和原任务续聊输入框。保持原 Claude 会话打开；离线时明确提示，不创建替代 CLI 会话。新建 Claude / 原生 App 会预填草稿，需在 Claude 检查项目并发送。文本续聊、原 ID、历史上下文、原 App 可见回复及完成回传均已验收，见 [接入记录](CLAUDE-APP.zh-CN.md)。
